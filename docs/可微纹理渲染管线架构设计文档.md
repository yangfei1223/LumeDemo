# 可微纹理渲染管线架构设计文档 (RDG 宏观循环 + Shader 内联微分)

## 1. 架构核心原则 (Design Philosophy)

本架构专为在成熟 3D 渲染引擎中进行**纹理参数优化（如逆向渲染、贴图重建）**而设计。 摒弃了传统可微渲染框架中“构建计算图 -> 追踪算子 -> 逆向生成 Adjoint Graph（伴随图）”的复杂逻辑。

- **RDG 即优化循环 (RDG as the Loop)**：整个引擎不引入任何 Autodiff 引擎。前向渲染、损失求导、参数更新直接被显式定义为 RDG 中的 3 个宏观 Pass。
- **极简 Pass 数量 (Minimal Passes)**：将 Loss 计算与反向传播强耦合在一个 Compute Shader 中，消灭不必要的中间梯度纹理。
- **内联微分 (Inline Differentiation)**：反向传播的数学逻辑（如双线性插值求导）封装为 GLSL 纯函数库，利用 GPU 的硬件原子操作（`atomicAdd`）直接打穿到全局梯度 Buffer 中。

------

## 2. 数据与资源抽象 (C++ RHI 层)

在引擎端，我们只需要扩展纹理对象，使其能够承载梯度和优化器状态，同时定义一个简单的结构来接收前向图形管线的 UV 输出。

C++

```
// 1. 可微纹理容器 (Differentiable Texture)
class DiffTexture {
public:
    uint32_t width, height;

    // 前向物理数据：常规纹理，供图形管线进行硬件纹理采样
    RHITexture* valueTexture;     

    // 反向梯度数据：一维 SSBO 数组，供 Compute Shader 并发原子累加
    RHIBuffer* gradientBuffer;    

    // 优化器动量数据：SSBO 数组 (用于 Adam 算法)
    RHIBuffer* momentum1Buffer;   
    RHIBuffer* momentum2Buffer;   

    // 初始化时分配，每次迭代前清零 Gradient
    void ClearGradient(RHICommandList* cmd) {
        cmd->ClearBuffer(gradientBuffer, 0);
    }
};

// 2. 上下文缓存带 (Context Tape)
// 由前向光栅化 Pass 输出，只记录求导必需的最小集 (UV)
struct RenderContextTape {
    RHITexture* screenSpaceUV; // 推荐格式: RG16F
};
```

## 3. Shader 微分数学库 (`DiffTextureLib.glsl`)

将纹理的求导与分发逻辑完全下沉为纯 Shader 库。业务层 Shader 像调 API 一样调用它。

OpenGL Shading Language

```
// --- DiffTextureLib.glsl ---
#extension GL_EXT_shader_atomic_float : require

// 1. 前向采样 (在 Fragment Shader 中调用)
vec4 DiffTex_Sample_Forward(sampler2D tex, vec2 uv) {
    return texture(tex, uv);
}

// 2. 反向梯度分发 (在 Backward Compute Shader 中调用)
// 将当前像素的 Loss 梯度，根据双线性插值权重，分发给 4 个相邻纹素
void DiffTex_Sample_Backward(vec2 uv, vec4 d_color, inout float gradBuffer[], vec2 texSize) {
    vec2 pixelPos = uv * texSize - 0.5; 
    vec2 pi = floor(pixelPos);
    vec2 pf = fract(pixelPos); 
    
    // 计算 4 个顶点的权重
    float w00 = (1.0 - pf.x) * (1.0 - pf.y); 
    float w10 = pf.x * (1.0 - pf.y);         
    float w01 = (1.0 - pf.x) * pf.y;         
    float w11 = pf.x * pf.y;                 
    
    // 边界钳制逻辑 (Clamp)
    int x0 = clamp(int(pi.x), 0, int(texSize.x) - 1);
    int y0 = clamp(int(pi.y), 0, int(texSize.y) - 1);
    int x1 = clamp(int(pi.x) + 1, 0, int(texSize.x) - 1);
    int y1 = clamp(int(pi.y) + 1, 0, int(texSize.y) - 1);

    // 计算 1D 偏移基址 (RGBA)
    int width = int(texSize.x);
    int idx00 = (y0 * width + x0) * 4;
    int idx10 = (y0 * width + x1) * 4;
    int idx01 = (y1 * width + x0) * 4;
    int idx11 = (y1 * width + x1) * 4;
    
    // 原子累加到目标纹理的全局 SSBO 中
    for(int i = 0; i < 4; ++i) {
        atomicAdd(gradBuffer[idx00 + i], d_color[i] * w00);
        atomicAdd(gradBuffer[idx10 + i], d_color[i] * w10);
        atomicAdd(gradBuffer[idx01 + i], d_color[i] * w01);
        atomicAdd(gradBuffer[idx11 + i], d_color[i] * w11);
    }
}
```

## 4. 极致融合：管线与 Shader 实现

将一次优化迭代极致压缩为 **3 个核心 Pass**，RDG 负责推导它们之间的屏障（Barrier）。

### Phase 1: Forward Graphics Pass (前向渲染)

保持引擎原有的光栅化优势，利用 **MRT (多渲染目标)** 输出画面和 UV。

- **输入**：`valueTexture`, 场景网格数据。
- **输出**：`ColorTarget`, `TapeUV`。
- **Shader 特征**：传统的 Vertex/Fragment Shader，内部调用 `DiffTex_Sample_Forward`。

### Phase 2: Fused Loss & Backward Pass (融合求导与反向)

**（核心亮点）** 这是一个 Compute Shader，按屏幕分辨率分发（Dispatch）。它直接将 Loss 计算与梯度累加融为一体，不产生任何中间纹理过渡。

OpenGL Shading Language

```
// FusedBackward.comp
#version 460
#include "DiffTextureLib.glsl"

layout(local_size_x = 8, local_size_y = 8) in;

layout(binding = 0) uniform sampler2D u_ColorTarget; // 前向渲染结果
layout(binding = 1) uniform sampler2D u_RefImage;    // 目标参考图
layout(binding = 2) uniform sampler2D u_TapeUV;      // 前向记录的 UV Tape
layout(std430, binding = 3) buffer TexGradBuf { float u_TexGrad[]; }; // 目标纹理的梯度缓存

uniform vec2 u_TexSize; // 正在优化的纹理分辨率

void main() {
    ivec2 pixelCoord = ivec2(gl_GlobalInvocationID.xy);
    
    // 1. 读取前向状态
    vec4 renderColor = texelFetch(u_ColorTarget, pixelCoord, 0);
    vec4 refColor = texelFetch(u_RefImage, pixelCoord, 0);
    vec2 uv = texelFetch(u_TapeUV, pixelCoord, 0).xy;

    // 如果该像素没有渲染到物体 (UV 无效)，直接剔除
    if(uv.x < 0.0 || uv.y < 0.0) return;

    // 2. 内联计算 Loss 的偏导数 (以 L2 Loss 为例: dL/dC = 2 * (render - ref))
    // 这一步的数据完全留在寄存器中，无需写回显存！
    vec4 d_color = 2.0 * (renderColor - refColor);

    // 3. 立即触发反向传播，写入全局 Buffer
    DiffTex_Sample_Backward(uv, d_color, u_TexGrad, u_TexSize);
}
```

### Phase 3: Optimizer Pass (参数更新)

一个 Compute Shader，按**纹理分辨率**分发（Dispatch）。

- **输入**：`gradientBuffer`, `momentum1`, `momentum2`。
- **输出**：覆盖写入 `valueTexture`。
- **Shader 特征**：读取梯度，执行 Adam 优化公式，计算步长并更新物理纹理的颜色值（代码参考上一版，此处省略以保持简明）。

## 5. C++ RDG 调度代码 (主循环)

在 CPU 侧，主控逻辑变得极度清晰：RDG 显式表达优化过程，抛弃 Autodiff 库。

C++

```
// 每一帧 (或每次优化 Iteration) 调用的构建函数
void BuildOptimizationGraph(RDGBuilder& builder, DiffTexture* targetTex, RHITexture* refImage) {
    
    // 0. 清零
    builder.AddClearPass(targetTex->gradientBuffer);

    // 1. 前向光栅化
    auto forwardPass = builder.AddPass<GraphicsPass>("Forward Render");
    forwardPass->Read(targetTex->valueTexture);
    forwardPass->Write(ColorTarget);
    forwardPass->Write(TapeUVTarget); // 写入 G-Buffer

    // 2. 融合反向计算 (Loss + Backward)
    auto backwardPass = builder.AddPass<ComputePass>("Loss and Backward");
    backwardPass->Read(ColorTarget);
    backwardPass->Read(refImage);
    backwardPass->Read(TapeUVTarget);
    // 声明读写依赖，RDG 会自动插入 Buffer Barrier
    backwardPass->ReadWrite(targetTex->gradientBuffer); 
    backwardPass->SetShader(FusedBackwardShader);
    backwardPass->Dispatch(ScreenWidth, ScreenHeight);

    // 3. Adam 优化更新
    auto optimizerPass = builder.AddPass<ComputePass>("Adam Update");
    optimizerPass->Read(targetTex->gradientBuffer);
    optimizerPass->ReadWrite(targetTex->momentum1Buffer);
    optimizerPass->ReadWrite(targetTex->momentum2Buffer);
    optimizerPass->ReadWrite(targetTex->valueTexture); // 更新最终纹理
    optimizerPass->SetShader(AdamOptimizerShader);
    optimizerPass->Dispatch(targetTex->width, targetTex->height);
}
```

------

**架构总结：** 这个最终方案将计算图的“宏观调度”交给了引擎原生支持的 RDG，将“微观求导”硬编码在了极简的 Shader 中。它彻底移除了框架层面的反向传播管理开销，以仅 3 个渲染/计算 Pass 的极小代价，实现了商业级 3D 引擎中的纹理微调闭环。
